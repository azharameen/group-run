## Challenges

### 1. Retro Commitments Not Becoming Work
Retro action items live in `sprint-status.yaml` and get ignored. Only story-scoped work ships. **Root cause:** no mechanism to convert retro items into actual stories. ST-2.7's ainvoke() timeout succeeded _because_ it was tied to a specific story.

### 2. 6 Pre-existing Test Failures — 4 Epics and Counting
HITL/KB 404 failures persist through Epic 0, 1, 2, and 3. Epic 3 was the deadline. Team is becoming desensitized — "those 6 failures are old, not my problem." This is how bugs reach production.

### 3. deferred-work.md Never Triaged
The file exists and accumulates items (ST-3.1 added 4 more) but nobody reviews decisions. Deferred items should be triaged at retro start, not just appended.

---

## Key Insights

1. **Retro items need story homes** — Ameen identified: "commitments aren't tied to specific stories, they just sit in YAML and get ignored." ST-2.7 proves story-scoped debt gets done.

2. **84% code reduction is achievable** — ST-3.2 went from 171 to 27 lines with zero patches. Aggressive refactoring works when scope is clear.

3. **Security review is maturing** — ST-3.1 caught path traversal and field mutation attacks. Code review is catching real vulnerabilities, not just style issues.

4. **Test coverage is strong when scoped** — 127 frontend tests in ST-3.7 because the story had clear acceptance criteria. Story-scoped tests work.

5. **Capping action items at 3 is necessary but insufficient** — Even 3 items won't ship unless they become stories. Quantity control doesn't solve execution.

---

## Significant Discoveries

1. **idea_id Security** — ST-3.1 discovered path traversal via `idea_id` in file operations. Fixed with `^[A-Z0-9-]+$` validation. Epic 4 HITL interrupts need same validation.

2. **LangGraph .wrapped Attribute** — ST-2.1 discovered (and Epic 3 confirmed) messages stored with `.wrapped` attribute, not raw list. Future checkpoint consumers need to handle this.

3. **Field Allowlist Pattern** — ST-3.1 review identified unrestricted `update_idea` as a vulnerability. Field allowlist `{"title", "signal_text"}` now enforced. Pattern should apply to all CRUD endpoints.

## Action Items (Capped at 3 with Solutions)

### 1. Fix 6 pre-existing test failures (Critical)
- **Problem:** HITL/KB 404 tests fail in every run across 4 epics
- **Solution:** Create ST-4.0 (Epic 4 prep story) that fixes routes or adds `pytest.mark.skip` with documented rationale to each failing test
- **Owner:** Dana/Amelia
- **Success criteria:** `pytest` runs with 0 unexpected failures; skipped tests have inline skip reason
- **Deadline:** Before any Epic 4 story is created

### 2. Retro commitments become Epic 4 prep stories (High)
- **Problem:** Retro action items live in YAML and get ignored — no execution mechanism
- **Solution:** Add "Retro Prep Stories" section to Epic 4 planning. Each action item becomes a numbered story (ST-4.0, ST-4.1, etc.) with acceptance criteria. No Epic 4 feature stories start until prep stories pass.
- **Owner:** Ameen
- **Success criteria:** Epic 4 sprint-status.yaml shows prep stories derived from Epic 3 retro before feature stories begin
- **Deadline:** Epic 4 planning session

### 3. Triage deferred-work.md with go/no-go decisions (High)
- **Problem:** deferred-work.md accumulates items without triage — ST-3.1 added 4 more
- **Solution:** Review every deferred item. For each: (a) resolve if fixed, (b) promote to Epic 4 story with AC, or (c) dismiss with written rationale. Update file with triage date and decision.
- **Owner:** Amelia/Charlie
- **Success criteria:** Every deferred item has timestamped decision (resolved/story/dismissed) with zero items in limbo
- **Deadline:** Before Epic 4 kickoff
