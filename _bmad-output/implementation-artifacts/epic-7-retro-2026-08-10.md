## Challenges and Growth Areas

### 1. CI Pipeline Initial Design Gaps (ST-7.1)
The initial CI spec had 20 adversarial review findings — the most of any story. Missing coverage thresholds, frontend lint, security audit, caching, venv isolation, git config, and artifact retention. **Root cause:** Initial spec was too optimistic about "simple" CI setup.

**Lesson:** CI specs need a checklist approach — don't rely on intuition for what a "basic pipeline" includes.

### 2. Windows Cross-Platform Compatibility (ST-7.7)
5 patches were needed just for Windows command alternatives (`Copy-Item` vs `cp`, `Invoke-RestMethod` vs `curl`, PowerShell venv activation). Documentation assumed Linux/Unix by default.

**Lesson:** Windows-first documentation standards need to be baked in from the first draft, not added as patches.

### 3. HITL SSE Race Condition (ST-7.5)
HITL tests created interrupts via API before page load, but the frontend only receives interrupts via SSE events — events published before the SSE connection is established are not retroactively delivered. This was a subtle timing bug that required a full review iteration to catch.

**Lesson:** SSE/streaming edge cases need documented reference patterns so future stories don't rediscover these gotchas.

### 4. Performance Test Design Complexity (ST-7.6)
12 patches were needed for SSE timing on streaming endpoints, generator exhaustion prevention, timing middleware skip patterns, and fixture isolation. Performance test design is inherently the trickiest layer.

**Charlie (Senior Dev):** "Performance testing is always the hardest layer. You're measuring the measurement tool, not just the system."

**Lesson:** Performance test design patterns should be documented as reusable guides.

### 5. Deferred Work Accumulation
Multiple stories deferred items:
- ST-7.2: pytest in production image, VITE_API_URL localhost limitation, healthcheck documentation
- ST-7.3: placeholder selectors, docker validation, stale server risk
- ST-7.5: test data isolation between parallel runs
- ST-7.6: module-level side effects, queue full test fragility

**Lesson:** Deferred work needs formal triage before starting the next major work phase.

## Key Takeaways

1. **100% retro follow-through is achievable** — Epic 6 commitments were all completed, proving that action items stick when they're tracked and visible.

2. **Adversarial review is compounding in value** — The team's initial spec quality improved across the epic. ST-7.1 had 20 findings, but ST-7.2 had 17, and the pattern shows the team is internalizing review feedback.

3. **CI pipelines need checklist-driven specs** — "Simple CI" is a myth. A thorough pipeline needs coverage, lint, security, caching, venv, git config, and artifacts — none of which are obvious without experience.

4. **Cross-platform is not optional** — Windows compatibility patches added up to 5+ changes across stories. Bake it in from the start.

5. **SSE/streaming needs documented patterns** — Race conditions in event-driven architectures are subtle and hard to debug without reference material.

6. **Performance testing is the hardest test layer** — 12 patches for ST-7.6 shows that measuring systems requires understanding both the system and the measurement tool.
