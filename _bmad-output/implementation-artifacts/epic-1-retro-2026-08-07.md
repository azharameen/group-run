## Successes

### 1. LangGraph Supervisor Architecture
The supervisor graph was our biggest technical risk, and it paid off. ST-1.4 caught 4 blocking issues in review - message filter, TypedDict state, error handling, agent singleton. If we hadn't reviewed per-story, these would have shipped and caused runtime failures.

**Key Decision:** Switching from "user" string filter to isinstance(m, HumanMessage) prevented subtle message routing bugs.

### 2. Clean Dead Code Removal
ST-1.3 and ST-1.10 surgically removed legacy FSM code without breaking anything. Deleting workflow.ts, removing validateGate(), cleaning SSE event filters - all verified with import scans. Zero TypeScript errors.

### 3. Streaming Architecture
The SSE streaming pipeline works end-to-end. astream(v2) to event bus to useChatStream to UI. The fetchCounterRef pattern for stale fetch guards prevents race conditions on rapid thread switches.

### 4. Test Infrastructure
ST-1.8 and ST-1.11 established solid test foundations. 24 backend tests with DB isolation (no filesystem writes), plus comprehensive frontend test suite. The in_memory_db fixture prevents test pollution.

### 5. Config File System
teams.yaml and mcp.json in project-root/config with schema version validation. This is declarative and auditable. Good call putting it at project root, not nested in backend.

---

## Challenges

### 1. Supervisor Graph Needed Multiple Review Rounds
ST-1.4 had 4 blocking issues caught in review. The initial version used a plain class for state instead of TypedDict, called the agent constructor on every invocation, and had unguarded error paths. It took two full review rounds to get green.

**Systemic Issue:** Complex state machine logic benefits from review earlier in the process, not just at the end.

### 2. useChatStream Hook - 11 Patches Applied
ST-1.9 was our most patch-heavy story. Removed token/reasoning fallbacks, added TypeScript interfaces, replaced alert() with toasts, fixed stale history fetch, fixed queue clearing, fixed AbortController signal, fixed stop not cancelling preflight. 5 items were deferred.

**Root Cause:** The spec did not fully anticipate the complexity of replacing the streaming protocol mid-flight.

### 3. Deferred Technical Debt Accumulation
ST-1.9 deferred 5 items: thread-scoped abort, O(n) transcript growth, partial SSE frame drops, concurrent send accumulator, global SSE events for other ideas. ST-1.4 noted asyncio.run() in MCP tools and missing timeout on ainvoke(). These will compound if not tracked.

### 4. Pre-existing Test Failures Carried Forward
The 6 pre-existing test failures (HITL/KB 404s) from Epic 0 are still unresolved. They are noise in our test suite - every time we run tests, we know 6 will fail, so we stop noticing when new ones appear.

### 5. No CI Pipeline Yet
We have a forbidden import script, but it is not wired into CI. We have tests, but they are run manually. ST-1.10 removed dead code, but without CI, nothing prevents dead imports from creeping back in.

## Key Insights

1. **Review Per-Story Is Non-Negotiable** - ST-1.4 caught 4 blocking bugs, ST-1.9 caught 11 issues. Without review, these would have shipped as production bugs.

2. **Config Validation at Startup Prevents Cascading Failures** - ST-1.2 and ST-1.5 added startup validation. Errors fail-fast with clear messages instead of manifesting as mysterious runtime failures.

3. **Singleton Patterns Work for Agent/StreamBus** - Module-level agent singleton and StreamBus singleton both proved the right choice. Agent rebuild elimination cut initialization time.

4. **Dead Code First then New Code Pattern Works** - Epic 0 cleaned dead code, then Epic 1 built on the clean foundation. When the codebase is clean, adding new features is faster.

5. **Complex State Machine Logic Needs More Upfront Design** - ST-1.4 and ST-1.9 both required significant rework. Implementation details around state transitions and error handling were under-specified.

---

## Significant Discoveries

1. **LangGraph astream v2 Changes Event Shape** - The response field is nested inside state_update, not flat. Required updating the entire frontend event handling pipeline. Epic 2+ depends on this event shape.

2. **DeepAgents Runtime Is Viable** - ST-1.5 proved DeepAgents runtime with MCP tools from config and team agents from teams.yaml works as a drop-in replacement for the old FSM agent system.

3. **SQLite Checkpointer Enables Thread Persistence** - The SqliteSaver checkpointer from ST-1.3 enables thread state persistence. Without it, Epic 2 would not be possible.
