- (decision) Product = Agentic Organization Platform: SaaS virtual org of AI agents. User creates an organization; teams of agents work autonomously but structured/guided/provable. Supervisor agent supervises teams, assigns idle agents, collects work items.
- (decision) Autonomy is step-wise destination, not v1: 'agents decide better than humans' is north star; get there via guardrails/checks ladder (HITL -> HOTL -> autonomous). Not immediate.
- (decision) Multi-tenant SaaS: yes, but isolation degree is a step-wise/phased decision (shared vs per-org DB).
- (decision) Idea-generation is a module within the org, gated behind a feature flag / higher subscription tier (premium/private capability). Subscriptions + add-on model later, not now, but architecture must not preclude it.
- (decision) Target user: solo founder OR small/medium/large team wanting to form a company. First vertical = software development company; later expand to other industries (medical, farming, etc.).
- (decision) Vision tagline: 'Build and manage virtual organization of AI Agents.' Product = SaaS virtual org of AI agents.
- (decision) Wow moment: user sees an idea generated that is NOT patented, with patentable + highly profitable + complete market research + roadmap + brainstorming from agents. Same idea hands off to Development team to build, then Test, then monetize, analytics, etc. Full lifecycle.
- (decision) Lifecycle path is configurable per organization and per modules user buys/subscribes/adds-on. No payments now, but capture subscription/tier points (feature flags, module gating) so monetization is not precluded.
- (decision) First screen = Command Center: single dashboard showing all work in progress, progress, highlights, teams/departments/agents. Initial org structure is FIXED/predefined (software dev company first), user runs it and profits. Custom org design is future/brainstorm.
- (decision) Future: human employees join org as supervisors/decision-makers/team members, or a separate module (e.g., collect customer feedback into platform for agents to act on). Not immediate; platform must be flexible to adapt. Provisions only.
- (decision) v1 = predefined best-practice set of departments/teams/agents/resources for a software development company. User runs org smoothly: development, financials, legal, salary, applications, resource cost -> proper departments/teams. User feels safe, maintains cost + production.
- (decision) Supervisor hierarchy: team supervisor (monitors only its team), department supervisor (only its department), top-level supervisor. Supervisor knows who does what/when/why/how, gives orders/requests, notes user-agent discussions, pitches in on contradictions. Need to define team vs department.
- (decision) Provable = full logging: references (where agents referenced from), why decisions taken, review that agent solutions have high/100% accuracy. Audit trail + provenance + accuracy review.
- (decision) Role names: Top-level = Chief of Staff. Department supervisor = Chief. Team supervisor = Captain. Aliases deferred.
- (decision) Provable/accuracy: deferred to brainstorming session. Options: scoring engine, ratings, self-review, peer review. Decide later.
- (decision) User can toggle modules/agents/teams on/off. Only Idea module is feature-flag protected (premium/private). No dynamic org design in v1 — just the toggle + flag.
